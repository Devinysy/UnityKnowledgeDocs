## 常见初始化顺序

| 回调 | 适合做什么 | 常见注意事项 |
| --- | --- | --- |
| `Awake` | 建立组件内部引用和不依赖外部顺序的初始化 | 对象可能仍处于禁用状态 |
| `OnEnable` | 注册事件、启动每次启用都需要的逻辑 | 可能被调用多次 |
| `Start` | 依赖场景中其他对象已完成 `Awake` 的初始化 | 只在首次启用后的第一帧前调用 |
| `Update` | 读取输入和逐帧逻辑 | 避免重复查找组件或大量分配 |
| `FixedUpdate` | 固定时间步长的物理逻辑 | 不要假设每帧恰好调用一次 |
| `LateUpdate` | 跟随、相机等依赖本帧更新结果的逻辑 | 仍需控制脚本间依赖 |
| `OnDisable` | 取消事件订阅、停止启用期间的资源 | 应与 `OnEnable` 成对设计 |
| `OnDestroy` | 释放对象生命周期内持有的资源 | 不要依赖其他对象仍然存在 |

## 推荐原则

1. 在 `Awake` 缓存自身组件引用。
2. 在 `OnEnable` 和 `OnDisable` 成对注册、注销事件。
3. 不使用脚本执行顺序掩盖结构性依赖，优先显式注入依赖。
4. 跨对象初始化顺序复杂时，建立独立的启动流程，而不是继续堆叠生命周期假设。

::: warning 版本与上下文
具体回调时机还会受到对象激活状态、场景加载方式、编辑器播放模式设置等影响。遇到边界问题时，应对照目标 Unity 版本的官方执行顺序文档并写最小复现。
:::
